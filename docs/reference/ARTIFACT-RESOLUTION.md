# Optional OCI release retrieval

`release::fetch_release` accepts an immutable `ReleaseReference` and trusted CI `RegistryAccess` settings. The reference binds both the OCI manifest digest and the digest of `release.json`; these are different identities. Tags, URL schemes, embedded credentials and malformed references reject before retrieval.

The resolver pulls the release in process with an OCI Distribution client; it runs no external tool. It uses HTTPS only, including for `localhost`, with the Mozilla root certificates plus an optional trusted CI CA file for a private registry's certificate chain. It does not enable insecure TLS. The whole retrieval, every layer included, has a five-minute deadline. Redirects, such as a blob served from a CDN, are followed a bounded number of times and only to `https://` locations; the registry's `Authorization` header is never sent to a different host. A `docker.io` reference is pulled from Docker Hub's registry host.

Authentication follows the Distribution token flow. The first request is anonymous. On a `Bearer` challenge the resolver requests a token from the challenge's HTTPS realm, with the configured credentials as HTTP Basic or anonymously without them, and retries with that token. A `Basic` challenge is answered only when credentials are configured. Credentials come only from the CLI's environment (below); Docker configuration files and credential helpers are not read.

The manifest is fetched by its reference digest, and its bytes, bounded to 4 MiB, must hash to that digest before they are parsed. An image index or Docker manifest list rejects; the reference must name an image manifest. As with `oras pull`, only layers carrying an `org.opencontainers.image.title` annotation are materialised and other layers are ignored. Each title must be a normal relative path: no absolute path, `.` or `..` segment, empty segment, backslash or control character, and a bounded length. Subdirectories are created; a repeated title, or a title that is another title's directory, rejects. The layer count and total declared size are bounded. Each layer streams into a fresh private directory, never buffered whole, and rejects once it exceeds its declared size; after download its size and SHA-256 digest must equal its descriptor.

Transport success does not authorize a release. `fetch_release` checks the downloaded `release.json` against the reference's protected digest and, once they match, returns `FetchedRelease`, which owns the temporary directory. This establishes content identity only; it does not check signatures or policy. The CLI separately calls `release::verify_candidate` against that path with an independently supplied `TrustPolicy`, covering payload integrity and signature policy, before treating the release as deployable. Dropping `FetchedRelease` removes the downloaded directory; persistent retention belongs to the external artifact registry. Failed retrieval returns no fetched handle. Registry response bodies, headers and tokens never appear in errors: retrieval fails with a generic message, or names the digest or path check that rejected the content.

The deployment CLI supports this retrieval boundary and applies the independently supplied trust policy to the requested release. Artifact publication for a complete signed release, retention policy, disk quota enforcement and a fresh-CI upgrade remain unverified.

## Deploy from an immutable reference

Supply `--artifact-reference FILE`, or set `APSIDES_RELEASE_REFERENCE` to that file and run `aps deploy`. The file is strict JSON with only `oci` and `releaseDigest` fields. `oci` must be a repository followed by `@sha256:` and the OCI manifest digest; `releaseDigest` must be the SHA-256 digest of the exact `release.json` bytes. Both hashes must come from the approved release publication. Do not substitute the controller image digest for either value.

`APSIDES_REGISTRY_CA` optionally names an absolute trusted CA file in PEM form. `APSIDES_REGISTRY_USERNAME` and `APSIDES_REGISTRY_PASSWORD` supply registry credentials; set both or neither, and the registry is accessed anonymously when neither is set. Inventory settings remain required. Explicit local `--artifact` and a configured remote reference are mutually exclusive.

The CLI retains the temporary download throughout the operation, discovers cluster policy from the release's declared scope using the existing bootstrap flow, and verifies the release under that protected policy. It compares the approved digest with the requested release before minting deployer credentials. The fetched-content type confers no deployment authority. The temporary files are removed when the operation ends; immutable registry retention must outlive CI and pod replacements.

This supports fetching the requested deployment artifact. A complete signed-release deployment from a fresh CI environment remains unverified.

OCI retrieval is optional distribution for a CI-supplied release. Normal upgrade and prune recovery must not retrieve a historical artifact. No OCI recovery location is written to protected transitions.
